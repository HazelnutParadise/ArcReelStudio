# 音效是独立、可重叠的音轨，有自己的音效库

剪辑时要能加音效：上传或用 AI 生成，放到时间线上，成片与剪映草稿都带上。BGM 已经有库与轨道，但它的规则（同一时刻只有一首、统一积分响度、默认淡入淡出各 1 秒）不适合短促、常常叠在一起的音效。决定如下。

**音效库与 BGM 库分开**：`project.json` 的 `sfx` 下登记每个音效，文件放 `sfx/<音效 ID>`，产物身份 `project-sfx`，依据只有文件字节的内容指纹，与 BGM 同一套登记方式。音效多半只有零点几秒到几十秒，积分响度对这么短的瞬态不稳定，所以改按实测峰值统一到 −1 dBFS（增益上限 24 dB），不沿用 BGM 的 −16 LUFS。

**音效轨可以重叠**：修订内容新增 `sfx` 片段（ID `s<n>`，编号分配器 `next_sfx_number`），按绝对起点摆放，只检查起点落在时间线内，不检查重叠；默认音量 1、不淡入淡出。超出时间线末尾的部分截断，截断处淡出 50 毫秒免得爆音。音效不在项目里时以 `sfx_missing` 阻断出片。

**渲染与依据**：成片把音效和 BGM 一起混进整集音频（共用同一种叠加输入），剪映草稿把重叠的音效分到最少的几条「音效」轨。成片与剪映草稿的依据在有音效时另收 `sfx`，没有音效时形态不变，所以加入音效轨不会让既有的成片与草稿读作过期。

**生成**：音效与音乐同属音频类型，以能力 `text_to_sfx` 区分（见 `docs/adr/0126`）；设定键 `default_sfx_backend` / `sfx_backend`，不自动推断。生成后端沿用音乐的「提示词 + 长度 → 音频」接口，新增端点 `elevenlabs-sfx`；Stable Audio 3 同时具备音乐与音效能力。任务类型 `sfx`，与音乐共用一段「解析模型、生成、记账」的步骤，结果登记进音效库。
