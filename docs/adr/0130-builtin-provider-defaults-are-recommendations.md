# 内置供应商的默认模型只作推荐

模型目录给每个内置供应商的每种媒体类型标了一个默认模型（数据字段 `defaults`）。此前全局与项目都没有设置默认模型时，运行时按供应商注册顺序挑第一个已配置供应商的默认模型来用；项目字段只写了供应商（如 `gemini-aistudio`）时也用它补全。两个问题：目录改一次默认，所有没设置的实例生成用的模型就悄悄变了；而 fork 的目录里 `audio` 的默认可以是音乐模型（Stability、ElevenLabs），只配了这两家时旁白配音会被挑成音乐模型。决定把目录的默认降为「推荐」，与上游 ArcReel 同一方向（上游 ADR 0099 修订、项目 schema v20），在连线中心（ADR 0122）上落地。

## 规则

**运行时不读推荐**：生成用的模型只来自项目与全局的模型设置。都没有设置时，只退到自定义供应商的默认模型；还没有就报「没有默认模型」，指向「全局设置 → 默认模型」。项目字段只写了内置供应商、没写模型时报 `model_not_selected`，不补全、不退到别的层；该供应商在这个媒体类型上根本没有模型时报 `model_not_in_provider_catalog`。任务载荷缺模型时回落到项目与全局设置，不补推荐。API 写入的模型字段必须是 `provider/model`，只写供应商的值被拒。

**首次配置写入推荐**：内置供应商的第一条连线生效时（API 金钥、Vertex 凭证上传与订阅登录三个入口都算），没有全局默认模型的 `text`、`image`、`video`、`audio` 写入它的推荐；已有设置不覆盖，任务类型桶与文本档位不写。写入只填 `provider/model`，不写连线旁键：没有旁键就用该供应商的默认连线，之后换默认连线会自动跟随，删除连线也不会被这次写入挡住。

**`audio` 只推荐配音模型**：`default_audio_backend` 在 fork 里专指旁白配音（TTS）。写入推荐、提示推荐变化时，`audio` 只取有 `text_to_speech` 能力的推荐；音乐与音效不写推荐，维持「没有设置就请用户设置」。

**推荐变化只提示，不替用户切换**：每种媒体类型至多一条提示：全局默认模型属于某个内置供应商、它的推荐变了且不是已见过的推荐；或全局默认模型为空、某个已配置的内置供应商给出了未见过的推荐（按注册顺序取第一个）。用户可以切换或保留，选过的推荐记为已见过，下次推荐再变才提示。已见过的推荐按供应商与媒体类型各存一条系统设置（`recommendation_seen:<provider>:<media>`），单句写入，只增不改，删掉连线再建不会吞掉未处理的提示。切换走全局默认模型的同一写入口：换了供应商时清掉连线旁键，同一供应商保留用户选的连线。

**项目 schema v20**：v19→v20 把项目模型字段里只写了内置供应商的值改写为 `provider/推荐模型`；没有推荐的、自定义供应商的值原样保留，运行时报 `model_not_selected`，由用户重新选择。只改写 `audio_backend` 等配音、文本、图片、视频字段，`music_backend` 与 `sfx_backend` 的裸值原样保留（音乐与音效没有推荐）。连线旁键不动：字段只补模型，供应商不变。归档导入时跳过用户停用的推荐模型（字段留裸值，导入后由用户选），其余入口（启动迁移、回收站与已删除项目的恢复、迁移重试）直接用目录的推荐。

**界面**：默认模型页在各通道旁显示推荐变化的提示；切换后把新值并进尚未保存的编辑，换了供应商时一并清掉表单里的连线旁键，免得之后保存别的字段把旧模型或不属于新供应商的连线写回。供应商的模型列表把推荐模型标为「推荐」。有已配置的供应商、却有媒体类型没有任何默认模型（自身、默认层都没设，自动预览也选不出）时，设置页列为配置问题。

## 没有照搬上游的部分

上游为已部署实例的升级另做了一套还原：记录升级前的数据库版本，按旧版本当时会挑的模型补上空的全局默认，项目迁移也按升级前的推荐补全。本项目从未部署，没有需要还原的实例，所以不做这套还原；v19→v20 用此刻的推荐，与上游归档导入的口径相同。

## 后果

- 目录改推荐不再改变任何实例生成用的模型，只在设置页提示。
- 只配了音乐或音效供应商时，旁白配音不会再被挑成音乐模型；没有配音模型就报错请用户设置。
- 已配置供应商、全局默认为空的开发实例，升级后生成会报「没有默认模型」，直到用户在提示上切换或手动设置。
- 上游 schema v20 的项目可以导入；v19 的项目导入时补全推荐。
