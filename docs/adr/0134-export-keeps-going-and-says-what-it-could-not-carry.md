# 导出只管导出：证明不了的产物状态照实带上并逐条告知，只因项目读不出、不安全或一直在变才停

项目归档导出要把每件产物的登记连同内容证据放进信封（`docs/adr/0062`），导入端据此恢复时效。导出过去对每条登记都要求重新证明成立，证明不了就整份导出失败：选中版本的快照文件不见了的视频、被外部替换的视频、文件已删的分镜图、对不上依据的字幕，任何一条都让导出请求返回泛用的 500。这些产物在源项目里照常可读（current、stale 或 missing），用户却连备份都导不出；删掉对不上的登记又会让导入后的产物读作 missing，诱导一次付费重生。

## 决定

- **导出不因产物状态失败。** 证明不了的登记只改变它怎么随包，并在导出诊断里逐条说明导入后它是什么状态；诊断随导出令牌返回，由导出诊断窗列出（`server/services/project/project_archive.py`，`lib/artifacts/artifact_activation.py` 的 `snapshot_preserved_artifact_manifest`）。
- **按正式文件补回不见了或损坏的版本快照。** 正式文件的内容指纹与版本记录的 `content_digest` 一致时，指纹一致即字节一致，按正式文件补回快照（快照不在，或在但与记录不符），记为自动修复。视频、参考视频、配音与带指纹的图片版本同一口径；仅当前版本的包不带的历史不补。补回的是普通文件：规划器把与正式文件同一个文件的快照当作证明不成立，硬链接会让补回的版本判 stale。导出只改导出副本，源项目不动；导入在判完时效之后对暂存目录做同样的补回，只让恢复版本与成片取材可用，不改这次的时效结论。
- **已过期的媒体不经导出洗成最新。** 源清单里视频或配音登记的内容事实与正式文件对不上时（源项目判 stale），不按它补快照；即使正式文件与快照一致，也只按 stale 保全。导出与导入的保全规划还要求快照与版本记录的指纹一致：正式文件与快照被一起换掉时，两者相同证明不了它就是那个版本。
- **视频与配音证明不了就以 stale 随包。** 正式文件在场，但证明不了它就是选中版本（快照不在或对不上、版本记录或选中版本缺失、版本属于别的集或剧本）时，登记照常随包、不带内容事实，导入后判 stale，与源项目一致。导入端同理：包里缺快照或快照对不上时，这条登记以 stale 导入，导入结果的警告逐条告知用户。这兑现了 `docs/adr/0062` 里「证明不成立的条目不带事实，导入后与源项目一样判 stale」；导入端不再因「正式文件与快照不一致」拒绝导入，只在包里的正式文件与信封指纹不符时拒绝。
- **正式文件已不在的登记不随包，引用也清掉。** 源项目里它已读作 missing，导入后同样是 missing，不丢任何信息。剧本条目或资产表里指向这类文件、又没有版本可恢复的引用，在导出副本里清空并记为自动修复，否则导入校验会拒收整个包。源项目里是符号链接的文件（判 blocked）同样处理，告知用户时说明它是链接、源项目里读不出。版本记录指向版本历史目录之外的，导入会拒收，导出副本里去掉这几条记录并告知。
- **字幕与呈现证明不了就不随包。** 字幕与旁白呈现是本地物化的结果，不调用任何供应商、不产生费用：导入后预览、剪辑或导出剪映草稿时按当时选中的媒体在本地重新物化。依据的媒体版本对不上，或依据的旧版本不在仅当前版本的包里时，登记不随包，诊断写明会免费重建。其余证明不了的登记同样不随包、文件照常在包里，导入时按文件重新判定。
- **产物清单读不出时按导出规划器自己的证明组信封。** 视频与配音、依据旧媒体版本的字幕与呈现按各自记录的生成依据登记，导入后照生成时的依据判时效，已过期的仍是 stale，不会变成 missing；其余产物没有别处记着生成依据，按当前内容登记，导入后判 current，诊断写明这一点。导入端从不读取源项目的清单文件（它是隐藏 sidecar，不进归档），`docs/adr/0098` 对「产物清单读不出」整项目拒绝的规定针对的是迁移与导入的项目本身，与这份备份无关。
- **只有这几类仍让导出停下，且带本地化原因：** 取快照时项目一直在变或快照期间依据被改动，返回 409 `export_project_busy`；项目文件、剧本、版本记录或宫格记录读不出（含没有读权限的文件与目录）、结构损坏或路径不安全，返回 422 `export_project_unreadable`，诊断给出项目内的相对位置；远端素材取不回，沿用 502 `material_remote_fetch_failed`。真正的意外错误仍是不泄露细节的 500。读不出的目录不再被略过：漏掉一整个目录的包比停下来更糟。

## 明确不采用

- **用登记的内容事实直接证明视频 claim、不补快照**：只解决视频 claim 本身。依据同一版本的字幕与呈现仍要读快照，导出照样失败；包里的版本记录也会指向不存在的文件，导入后恢复版本与成片取材都不可用。信封里也没有内容事实可供导入端使用。
- **丢掉证明不了的视频与配音登记**：导入后读作 missing，把一件可用的产物变成一次付费重生的邀请。
- **原地修复源项目的快照**：导出是只读路径，修改源项目超出它的职责；原地修复另行处理。

## Consequences

- 收窄 `docs/adr/0062`：「其他原因证明不了的条目照常让导出与导入失败」只剩导入端的内容证据不符；导出不再因此失败，导入端对在场正式文件、证明不了的视频与配音登记按 stale 恢复并告知。
- 收窄 `docs/adr/0098`：导出不再因产物清单读不出而失败，改为按文件组清单导出并告知。
- 源项目里选中快照不见了的视频，原地仍不能恢复该版本、也不进成片取材；这只靠原地修复解决，本决定不涉及。
- 改过版本记录的指纹、又删掉快照的包，导入后补回的快照是被改过的那份字节；登记仍按 stale 导入，用户主动切回这个版本才会按它重新登记。包本身不是安全边界：能改写包的人本可以把正式文件、快照与信封一起改成一致。
