# Project Schema Migrations

新增或修改 `lib/project/project_migrations/` 里的一步迁移，或改动产物补录规划器（`lib/artifacts/artifact_planner.py`）时按此文档工作。迁移链的结构、备份命名与失败裁决的机制见 `docs/adr/0062`；链只接 schema 19 及以上的项目，更早的一律拒绝（`MINIMUM_PROJECT_SCHEMA_VERSION`，`docs/adr/0131`）。本文档只放代码里查不到的约定。

## 步骤

1. **列出这一步要处理的全部旧形态。** 每种形态是「某个版本之前的代码写出的、与当前代码期望不同的数据」；下表是 v19 起的数据仍可能带着的已知清单，新发现的形态先补进表里。完成判据：每种相关形态在 `tests/legacy_project_shapes.py` 里有一个构造出的样本。
2. **写迁移器，登记与跳过都要有出口。** 一个发行版至多新增一步迁移：`CURRENT_PROJECT_SCHEMA_VERSION` 比最近的 `v*` 发版 tag 上的值大，说明最新一步尚未发版，改动并进这一步；两者相等才新开一步。改写产物清单的迁移返回 `ArtifactBackfillOutcome`（`lib/project/project_migration_report.py`），runner 把链上最后一份折进项目内的 `.migration_report.json`。规划器里每一条「不登记」的分支调用 `_skip(...)` 给出原因，用户该看到的再带上 `category`：`unreadable`（产物文件读不出）或 `legacy_audio_basis`（旧版配音缺 TTS 设置）。不带 `category` 的跳过是依据算不出，读时报 missing，不进报告。完成判据：每一条带 `category` 的跳过都出现在迁移报告里。
3. **在旧形态样本上跑到用户口径。** 除迁移器本身的断言外，至少一条用例用 `WorkflowStateService.get_project_summary` / `get_status` 或演示读模型断言用户看到的结果（计数、状态、预览可用）。完成判据：`tests/integration/lib/project/project_migrations/` 下的用例覆盖了从 v19 到当前版本的整条链（`migrate_project_dir`），不只单步。
4. **同步面向用户的迁移说明。** `website/docs/ops/deployment.md` 的「项目结构迁移」一节描述备份、报告与重试行为；行为变了就改它。
5. **抬高链的起点时一并删代码。** 起点（`MINIMUM_PROJECT_SCHEMA_VERSION`）抬高后，只服务更早版本的迁移步、链首规整与规划器口径分支一并删除，下表随之删掉不再可达的行；删分支前后对当前 schema 项目规划一次，依据摘要必须不变（`tests/integration/lib/artifacts/test_planner_basis_digest_guard.py`）。

## 已知旧形态

| 形态 | 出现版本 | 现在的期望 | 处理 |
| --- | --- | --- | --- |
| 旁白音频版本记录没有 TTS 设置 | ≤ 0.26 | `tts_*` + `artifact_audio_basis` | 不补写，进迁移报告「未能带入」 |
| 脚本规划草稿是 `.md`（`step1_*.md` / `script_plan_*.md`），没有 JSON 正式计划 | ≤ 0.26 | `drafts/episode_N/script_plan_*.json` | 不改文件；剧本依据不以脚本规划为输入，照常登记 |
| 源文用上传原名，没有 `source/episode_N.txt` | ≤ 0.26 | `source/episode_N.txt` | 不改文件；只影响脚本规划自身的登记，剧本照常登记 |
| 剧本顶层没有 `episode` 字段，或与绑定的集号不符（旧版同步与保存都接受缺集号的剧本） | 任意 | 顶层 `episode == 绑定集号` | 链首规整：以账本绑定为准写回，剧本先做版本化备份；进「已调整」。激活预检的同一判据留作守卫，schema 已是当前版本的归档导入仍由它拒绝 |
| 同一资产表里名字去两端空白、Unicode NFC 后相同（不区分大小写），或归一后为空 | 任意 | 资产名归一后唯一且非空，只差大小写也算重名 | 链首规整：留第一条，其余从资产表去掉，资产图文件不动，改前的 `project.json` 留作保留副本。去掉的条目名下的衍生按资产合并的规则并进保留条目（与已有衍生只差大小写的并入已有的那个），迁过去的衍生图搬到保留名下，清单登记换键并改路径（依据摘要不变），版本历史换键；并入已有衍生的撤掉清单登记与版本历史，图与快照文件留在盘上。被去掉条目本体的资产图登记撤掉、不换键（与改指资产图时撤掉落点上的登记同一口径）：只差大小写的有自己的键，一律撤；只差空白或 Unicode 形态的与保留条目共用一个键，只撤登记在被去掉条目的图上的那条（两边的路径先按运行时的解析归到项目相对写法，`./`、反斜杠都认得出），登记在保留条目的图上或路径落在项目之外、写法认不出时不动；保留条目原本没有登记就读作缺失；本体版本历史不动。只差大小写时，各集剧本与草稿里的引用（引用数组、说话人、`@` 提及、`变体/衍生`）按合并改写为保留名，已确认的脚本规划随之平移确认指纹；引用与登记先于删资产的 `project.json` 落盘，重跑可收敛。每处删除、衍生去向与每集的引用改写都进「已调整」 |
| 资产图、参考图或参考音频指向别的资产名下的文件（旧版资产创建与 PATCH 接受任意路径）；资产图也可能指向另一资产的衍生图；共用时两个条目声明同一路径，规划器拒绝整个项目 | 任意 | 资产图与参考文件按名归属，只指向本资产名下的文件（`owns_named_file`），新写入的别处路径被拒绝 | 链首规整：复制一份到本资产名下并改指过去，原文件留给它的主人；本资产名下的落点已被另一份内容占着时那一份先挪成保留副本，资产图落在类型目录本级，商品原图取最小的空闲序号；角色参考音频目录之外的参考音频本就不生效，不复制；进「已调整」。复制落点、资产图清单登记与改指在同一事务里提交，失败一并回滚；源路径含符号链接时不复制，复制目标目录为符号链接时拒绝，目标文件为符号链接时替换链接本身、不跟随其目标：登记在旧路径上的换到副本、依据摘要不变（同字节，时新的仍时新）；登记在落点上的描述的是被挪走的那份，撤掉（改指前后都读作缺失）。之后改名、删除、恢复与清空/替换参考音频都只处理本资产名下的文件 |
| 剧本条目缺 id 或 id 重复 | 任意 | 每个条目 id 非空且在剧本内唯一 | 链首规整：缺的补新 id，重复的从第二条起换新 id；换号条目上指向原 id 规范媒体路径的引用清空（文件属于保留原 id 的条目），只描述这些媒体的生成状态（缩略图、视频 URI、宫格归属、生成时刻）一并清空，落盘的 `status` 按剩下的媒体重算；剧本先做版本化备份；进「已调整」 |
| 两集里有同号条目（旧版只在本集内判重，复制来的剧本可与另一集同号，两边认领同一个媒体文件） | 任意 | 条目 id 在项目内唯一 | 链首规整：媒体与登记归 id 前缀 `E<n>` 所指的那一集，前缀对不上任何一个同号集时归账本里靠前的那一集；另一集的条目在本集换新 id（也避开其他集在用的 id），指向原 id 规范媒体路径的引用清空，不删文件；本集已没有条目持有原 id 时，本集名下原 id 的登记（分镜图、视频、配音、字幕、呈现）撤掉、不换键，先于剧本落盘，重跑可收敛；本集内重复 id 的第一条仍持有原 id，它的登记不动；本集宫格记录的成员名单列着撤掉的原 id 时，规划器找不到成员、投影不出这张宫格，宫格与它切出的分镜图的登记同一步撤掉，宫格记录与图文件不动；剪辑时间线里引用原 id 的片段不改写（截取点绑在原 id 的视频版本上），读作单元已删除；项目级版本历史里原 id 的记录仍归保留它的那一集，不动；进「已调整」 |
| 单个宫格记录、单份脚本规划草稿读不出（不是合法 JSON 或不符合模型） | 任意 | 可读 | 激活模式（迁移与归档导入）下文件原样保留、不登记，进报告「未能带入」（宫格列的是记录文件）；该宫格的切格分镜一并不登记。运行期规划照旧报错 |
| 源文不是 UTF-8 | 任意 | 可读 | 草稿本身读得出、只是依据算不出：激活模式下脚本规划不登记、读时报 missing，不进报告 |
| 媒体文件读不出（权限、损坏） | 任意 | 可读 | 激活模式下原样保留、不登记，进「未能带入」 |
| 视频或配音的正式文件在，选中版本的快照文件不在（手工打包或清理过版本目录） | 任意 | 选中快照与正式文件同字节 | 激活模式下正式文件原样保留、不登记，按读不出进「未能带入」（`unreadable`）；正式文件本身不在时读作缺失、不进报告（先看正式文件，快照读不读得出都一样）；快照是符号链接或非普通文件时只记账。带信封的归档导入里源项目已登记的这类视频与配音按 stale 恢复，不进报告、进导入结果的警告；正式文件与版本记录指纹一致时，导出先在导出副本补回快照；带信封的导入在判完时效后补回快照，无信封的导入在自证补录前补回，这类视频照常登记（`docs/adr/0134`） |
| 归档里的剧本引用了未定义的角色、场景或道具 | 任意 | 引用的资产都有定义 | 导入时补一条空白定义（诊断 `placeholder_{character,scene,prop}_added`；场景与道具过去拒绝导入），进「已调整」 |
| `project.json` 没有 `aspect_ratio` 字段（新建项目一律写入） | 很早期版本或导入项目 | 分镜图画布按项目比例规则取缺省值：解说与广告 9:16、剧情 16:9 | 不补字段，不改写登记；剧情项目此前按 9:16 登记的分镜图读为过期 |
| 带信封的归档里，因生成缺口（分镜提示词待补、引用资产缺资产图、原图读不到、描述为空等）在源项目没有登记的产物 | 任意 | 缺口只拦生成，依据照常投影，缺口记为缺席（`docs/adr/0098`） | 导入激活按缺口规则（`plan_artifact_target_state_by_gap_rule`）改前改后各规划一次，只补录信封里没有 claim、改前没有目标、改后有的条目，读作 current；已登记条目逐字节不变 |
| `project.json` 的模型字段（文本、图片、视频与配音的默认、档位与任务类型桶）只写了内置供应商（裸 `ark`、两端带空白或缺模型的 `openai/`），升级前的运行时按模型目录里该供应商当时的默认模型补全 | schema ≤ 19 | `provider/model`；运行时不再按目录推荐补全（`docs/adr/0130`） | v19→v20 按迁移这一刻目录的推荐补全（配音只用能文本转语音的推荐）；归档导入另外跳过用户停用的推荐。没有推荐的值与 `music_backend` / `sfx_backend` 的裸值原样保留，运行时报「没有选定模型」，由用户重新选择；自定义供应商的裸 id 原样保留，运行时落到下一层；连线旁键不动 |

## 约定

- 升级路径常常跨多个版本：迁移要处理的是 v19 以来各版本留下的全部变体，不只上一版写出的标准形态。
- 备份走 `lib/project/project_migrations/backups.py`；runner 在每一步之前备份 `project.json`，备份按起点版本命名（`*.bak.v<起点版本>-*`）。
- 改写清单的迁移先做只读预检再落盘。
- 整份激活会把在场产物一律登记为时新。改的只是某个依据输入、既有产物本不该因此过期时，改前改后各规划一次目标态，只把「改前正是时新、且目标登记变了」的条目改写过去，本就过期的条目不被伪造成时新。带信封的归档导入在迁移前把信封里的 claim 落成暂存清单（`stage_preserved_artifact_claims`），迁移链像原地升级一样改写它们，改写清单的迁移步不必为归档另写路径；导入激活再按内容证据恢复迁移后的 claim。
- 过去正常流程写出的旧形态在链首统一规整：`legacy_shapes.normalize_legacy_shapes` 在链上第一步之前跑一次，之后的迁移步与规划器只见规整后的形态。新发现的这类形态加到这里，不在各步里各自拒绝。因数据拒绝整个项目只限 schema 早于 v19、`project.json` 或剧本读不出、`versions.json` 或 `.arcreel_artifacts.json` 读不出、剧本条目结构损坏与导入包不安全；规划器的容错只在激活模式（`_activation_mode`）下生效，运行期行为不变。
- 早于 v19 的项目（含缺 `schema_version` 读作的 v0）在 `migrate_project_dir` 读出版本后、规整与任何备份之前就以 `schema_unsupported_error` 拒绝（码 `project_schema_unsupported`，参数 `version`、`minimum`）；源文件编码迁移也跳过它。启动期与整项目恢复只写失败裁决 `.migration_failure.json`、继续下一个项目，阻断码与下一步分别是 `project_schema_unsupported` 与 `upgrade_project_upstream`，不走修复后重试。归档导入在解包后、修复与编码迁移之前预检，以 `arch_project_schema_unsupported` 返回 400。
- 规整的每处改动记成 `MigrationAdjustment`（报告「已调整」），读不出而原样留下的文件记成带 `category` 的跳过（报告「未能带入」）；报告只有这两栏。依据算不出（生成缺口、没有版本记录、路径不规范、源文不是 UTF-8 等）的跳过不带 `category`，由 `write_migration_report` / `extend_migration_report` 滤掉；需要重新规划的单位也不进报告：带 `needs_replan` 的条目，其分镜图、视频与配音由 `write_migration_report` 统一从「未能带入」里去掉，不靠各条跳过路径各自记得。归档导入不分 schema 版本，把导入激活没能登记的产物与修复期补的占位一并并进报告（`extend_migration_report`）。链中途失败时，已做的调整写进一份 `complete: false` 的报告，重试时并入下一次报告；未完成的报告不对用户显示。链在提交当前版本之后才失败（最后一步提交后报错，或收尾那次写报告失败）时重试不再进链，runner 见到项目已在当前版本、报告仍未完成，就把它补写成完成的报告。已发版的调整码（含已删规整项的码）留在 `MigrationAdjustmentCode` 里，存量报告照常读出与显示。
- 有取舍时被替下的那份用 `backups.set_aside_as_kept_copy` 留作保留副本（`<name>.kept.v<N>-<ts>`），不被 `cleanup_stale_backups` 清理，路径写进调整条目的 `backup`；只是改写的文件照常做版本化备份。
- 生成缺口不等于「投影不出来」：缺口只拦生成，期望依据照常由已有的输入值构造，缺的项记在依据的 `absent` 里（`lib/artifacts/input_gap.py`）；没有缺口时依据不写这个键，输入完整的已登记条目摘要不变。
- 依据确实算不出的目标不登记，读时报 missing；这不等于「不存在」，也不等于「整项目失败」。其中只有文件读不出（规划器 `artifact_unreadable` 阻断）进报告，其余不进。归档导入只在报告非空时要求确认，当前代码导出的健康项目再导入不弹确认、不留报告。
- 规划口径放宽、原先跳过的产物现在能登记时，改前改后各规划一次，只补「改前没有目标、改后有、清单里也没有」的条目，已登记条目一律不动。带信封的归档导入按同一差集补录信封里没有 claim 的产物（`gap_backfill_entries`）。
- 迁移不推进项目的最近活动时间：`project.json` 与剧本的 `metadata.updated_at` 保留原值，新写出的剧本不以迁移运行的时刻作为 `updated_at`；不调用 `lib.project.project_activity.record_project_activity`，也不经过调用它的业务写入出口（草稿、正式脚本规划写盘事务、剪辑时间线存储、项目记忆）。
